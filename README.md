# Whodeployed

> The dashboard is green and it's lying.

**Whodeployed** is a browser-based deduction game about production incidents. You get paged, you ask the system questions, you form hypotheses, you mitigate — and you learn observability the way it is actually practiced: by investigating with incomplete signals under time pressure.

Progression is not about unlocking tools. Every signal (metrics, logs, traces, deploy events) is available from incident #1. What grows is the **repertoire of questions you know to ask** — from "show me the dashboard" to "what changed in the last 30 minutes?" to "I'm declaring mitigation without a root cause".

## Status

🚧 **Phase 2 — Text prototype.** There is no game yet.

Phase 1 is done: the **engine** is out as [`engine-v0.1.0`](https://github.com/jeffersonvalente/Whodeployed/releases/tag/engine-v0.1.0). It is a deterministic simulator of the fictional shop with 6 fault kinds, and it generates coherent metrics, logs, traces and deploy events, the same bytes for the same seed. It runs on its own, as a command-line tool that writes NDJSON or as a TypeScript library; see [`packages/engine/README.md`](./packages/engine/README.md).

Next is a plain-HTML prototype of 3 incidents, tested with a junior engineer before any game UI is built. Follow along in [`SPEC.md`](./SPEC.md) and the gates in [`docs/gates/`](./docs/gates/).

## Who is this for

- **Junior/mid devs and ops** who have seen a dashboard but freeze when the alert fires.
- **Senior engineers and SREs** running onboarding, workshops or meetups — and contributing the incidents that scarred them.

## What it is not

- Not a full observability course. No SLO design, no OTel instrumentation, no alerting theory in v0.x.
- Not a Grafana clone with sprites. Telemetry is simplified and generated by a deterministic engine.
- Not a quiz. There are no multiple-choice answers. You ask for data and you decide.

## How it will work (v0.1)

One fictional shop (`gateway`, `auth`, `catalog`, `cart`, `payment`, `orders-worker`, `postgres`, `redis`, `queue`). Eight incidents of increasing difficulty, each planting one real-world trap: the green dashboard hiding a saturated dependency, the retry storm where the loud service is not the guilty one, the noisy alert with no impact. A post-incident review shows you what you asked that you didn't need to, and which signal already had the answer.

Everything runs in the browser. No install, no backend, no account.

## Running

The game is not playable yet; Phase 3 ships it as a static site. The engine runs today (Node.js 22 or later):

```sh
npm install https://github.com/jeffersonvalente/Whodeployed/releases/download/engine-v0.1.0/whodeployed-engine-0.1.0.tgz
npx whodeployed-engine simulate --seed demo --ticks 60 --fault connection_pool_exhaustion | head -n 3
```

## Contributing

The best contribution is **an incident you actually lived through**, written as a scenario YAML. See [`CONTRIBUTING.md`](./CONTRIBUTING.md). The scenario format is in `SPEC.md`, section 7.

## Why open source

Because the point is for it to exist, be used, and collect real incidents from the SRE community — not to sell it.
